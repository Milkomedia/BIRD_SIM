# BIRD_SIM

BIRD_SIM is a research-oriented MuJoCo simulator for an articulated, bird-like
flapping-wing vehicle. The project combines a 12-joint rigid-body wing model
with strip-based unsteady aerodynamics, actuator dynamics, real-time
visualization, and a separate telemetry monitor.

> **Project status:** active research prototype. The current default scene is a
> fixed-base aerodynamic test configuration. A flight controller and control
> allocation layer are not implemented yet.

## Current features

- MuJoCo model with six joints per wing and mirrored left/right geometry
- Real-time C++17 simulation at 5 kHz with a separate approximately 60 Hz
  rendering path
- Modified strip-theory model using 76 strips in total
  - humerus: 7 strips per wing
  - radius: 6 strips per wing
  - manus: 25 strips per wing
- Bilinear aerodynamic-coefficient lookup in angle of attack and Reynolds
  number for the humerus, radius, and manus airfoil datasets
- Goman--Khrabrov-style dynamic-stall correction with separate upper- and
  lower-surface separation states
- Two-state Wagner/Jones wake-memory correction
- Translational and rotational added-mass effects
  - acceleration-dependent inertia is added to MuJoCo's generalized mass
    matrix
  - velocity-dependent bias loads are applied as external wrenches
- Ellipsoidal body-fluid model including drag, lift, Magnus, angular-drag, and
  virtual-inertia bias terms
- DC motor, gearbox, ESC lag, PD servo, torque saturation, rotor inertia, and
  joint damping models
- Optional CRSF/ExpressLRS input
- In-viewer visualization of strip frames, aerodynamic forces, velocity,
  acceleration, angular velocity, and angular acceleration
- Schema-described shared-memory telemetry with live plotting and replay

## Requirements

The current development target is **macOS**. In particular, the CRSF serial
implementation uses Apple's `IOKit/serial/ioss.h`. The aerodynamic and logging
code is otherwise largely platform-independent, but Linux support requires a
portable serial backend or disabling `ELRS.cpp`.

Required C++ dependencies:

- CMake 3.16 or newer
- C++17 compiler
- MuJoCo 3.11 (current development target)
- GLFW 3
- Eigen 3
- POSIX threads and memory mapping

Required Python packages for the telemetry monitor:

```bash
python3 -m pip install numpy PyQt5 pyqtgraph
```

## Build

Clone the repository and configure a release build:

```bash
git clone https://github.com/Milkomedia/BIRD_SIM.git
cd BIRD_SIM

cmake -S . -B build \
  -DCMAKE_BUILD_TYPE=Release \
  -DCMAKE_PREFIX_PATH="$CONDA_PREFIX"
cmake --build build --parallel
```

`CMAKE_PREFIX_PATH` may be omitted when MuJoCo, GLFW, and Eigen are already in
CMake's default search paths. If MuJoCo is installed elsewhere, pass the
directory containing `mujocoConfig.cmake` through `CMAKE_PREFIX_PATH`.

## Run

Start the simulator with the default scene:

```bash
./build/run
```

A different MuJoCo XML file can be supplied as the first argument:

```bash
./build/run /absolute/path/to/scene.xml
```

When an ELRS receiver is not detected during startup, the current fallback test
case uses:

- synchronized right/left flapping at 3 Hz
- flapping amplitude of +/-90 degrees
- a steady wind vector of `(-10, 0, 0)` m/s in the internal NED convention
- selected joint commands from the MuJoCo UI sliders

The default `mujoco/bird.xml` has the body's `freejoint` commented out, so the
vehicle is fixed in space. Re-enabling free flight requires restoring the
`freejoint` and selecting an appropriate initial condition and controller.

### Viewer controls

| Input | Action |
|---|---|
| `Space` | Pause or resume simulation |
| `Backspace` | Reset simulation and aerodynamic memory states |
| `Esc` | Exit |
| Left drag | Rotate camera |
| Middle drag / scroll | Zoom |
| Shift + right drag | Apply a translational perturbation to the selected body |

The right-side UI also selects the displayed strip quantity (`none`, `v`, `a`,
`w`, or `wdot`) and exposes joint-command sliders.

## Telemetry monitor

While the simulator is running, it publishes a schema-described 250 Hz ring
buffer to:

```text
/tmp/bird_sim.mmap
```

The in-memory ring holds the latest 3 seconds. Start the live monitor in a
second terminal:

```bash
python3 viewer.py
```

The monitor provides Flight, Joint, Strip Flow, Strip Loads, Strip Segment,
and raw Channel Browser views. Unless `--no-record` is specified, it saves the
full observed session as a compressed `.npz` file and also copies the final
`.mmap` snapshot under `log/` when the monitor closes or the simulation session
changes.

Replay a saved recording with:

```bash
python3 viewer.py log/npz/<recording>.npz
python3 viewer.py log/mmap/<recording>.mmap
```

Useful options:

```bash
python3 viewer.py --mmap /tmp/bird_sim.mmap \
  --log-dir log \
  --update-ms 40
python3 viewer.py --no-record
```

## ELRS/CRSF input

The receiver interface expects 16 packed CRSF channels at 420000 baud. The
serial device is currently hard-coded in `include/ELRS.hpp`:

```cpp
static constexpr const char* DEVICE = "/dev/cu.usbserial-DU0E4O7H";
```

Change this value to match the local receiver. A valid CRSF frame must be
received during the startup probe for ELRS control to be enabled. The present
mapping commands the coupled wing joints and uses three auxiliary channels to
set external wind components.

## Model conventions and configuration

- Vehicle states and aerodynamic loads use NED/FRD conventions internally.
- MuJoCo rendering uses its FLU world convention; conversions are performed at
  the simulator boundary.
- Main simulation, geometry, motor, and timing parameters are defined in
  `include/params.hpp`.
- Aerodynamic lookup tables are stored in `include/coeff/coeff.hpp`; the source
  CSV files and conversion script are in `include/coeff/`.
- The current lookup domain is angle of attack `[-10, 25]` degrees and Reynolds
  number `[28753, 215645]`. Queries outside these ranges are clamped.

Key default rates:

| Quantity | Current value |
|---|---:|
| Simulation step | 200 us (5 kHz) |
| Render period | 16.667 ms (approximately 60 Hz) |
| Telemetry rate | 250 Hz |
| Telemetry ring duration | 3 s |
